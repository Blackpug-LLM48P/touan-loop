# answer-sheet-review（答案の分析）

返ってきた答案から、次の復習プリントの材料を作る。

## 入力

- 答案の写真（**氏名・クラス・番号を隠したもの**）
- あれば模範解答、配点

写真は `data/` に置く（このフォルダは push されない）。

## 作業する場所

touan-loop を clone したフォルダの直下で作業する。`data/` はそこからの相対パス。
`data/` が push されないのは、このフォルダの `.gitignore` があるため。別のフォルダで作業しているときは、始める前に親に伝え、touan-loop のフォルダに移ってもらう。

## 最初に確かめること

写真に氏名・クラス・番号が写っていたら、読み取りを始める前に親に伝え、隠したものを送り直してもらう。写っていた内容を、記録・ファイル名・返答のどこにも書かない。

## 手順

1. 問の一覧を作る（大問・小問の番号と配点）。
2. 問ごとに、次の3つを**別々に**記録する。
   - **読み取り**：子どもが書いた答え
   - **採点**：○×や点数（採点記号から分かること）
   - **原因**：なぜ落としたか
3. 回ごとのフォルダに保存する（下の「保存する場所」）。
4. 点数を照らし合わせる（下の「点数の照合」）。スクリプトの結果を、そのまま親に伝える。
5. 親に傾向を短くまとめて伝える。
6. 親に確かめてほしい点（読めなかった所、原因が仮説の所）を一覧にする。
7. 同じ教科の前の回があれば、くらべる（下の「前の回とくらべる」）。

## 保存する場所

1回のテストにつき1つのフォルダを作り、その中に `analysis.json` を置く。前の回のファイルを上書きしない。

```
data/2026-11-rika/analysis.json
data/2026-11-eigo/analysis.json
```

フォルダ名は「年-月-教科」。氏名・クラス・学校名を入れない。

## 守ること

- **読めない字は推測しない。**「読めなかった」と書く（`read.status: "unreadable"`）。
- 答えが読めなかった問の原因は、確定にしない（`hypothesis` か `unknown`）。
- 採点記号が読めれば、答えの字が読めなくても採点は記録してよい。
- 合計が合わないとき、合うように数字を直さない。「合わない」と報告する。
- 原因を確定（`confirmed`）にしてよいのは、答案に書かれたものが根拠になるときだけ。根拠は `cause.text` に書く（例：答案の式が「7.9÷10」）。
- 答えの数値だけから計算の間違い方を決めない。途中式が答案にないときは `hypothesis` にする。
- 満点の問は `cause` を `null` にする。失点のある問は、分からなくても `cause` を書く（`status` を `unknown` に）。
- 何も書いていない問は、`read.text` を「空欄」にする（`status` は `read`、`tag` は `blank`）。
- 原因は、答案から言えることだけを書く。性格や努力の話にしない。

## analysis.json の形

```json
{
  "subject": "理科",
  "total": {"max": 100, "got": 62},
  "questions": [
    {
      "q": "2(1)",
      "read":  {"status": "read", "text": "2.7"},
      "score": {"max": 3, "got": 1},
      "correct": "2.7 g/cm³",
      "cause": {"status": "confirmed", "tag": "condition", "text": "単位を書いていない"}
    },
    {
      "q": "3(2)",
      "read":  {"status": "unreadable", "text": null},
      "score": {"max": 4, "got": 0},
      "correct": "…",
      "cause": {"status": "unknown", "tag": null, "text": null}
    }
  ]
}
```

- `read.text`：答案に書かれていたもの。途中式があれば式も書き写す
- `read.status`：`read`（読めた）／`unreadable`（読めなかった）／`parent_confirmed`（親に確かめた）
- `cause.status`：`confirmed`（答案から確定）／`parent_confirmed`（親が本人に確かめた）／`hypothesis`（仮説）／`unknown`（不明）
- `cause.tag`：`keyword`（用語）／`question_form`（問われ方の読み違い）／`condition`（条件・単位・字数の見落とし）／`blank`（空欄）／`kanji`（漢字）／`procedure`（手順・計算）／`concept`（理解）

## 点数の照合

次の3つを別々に確かめ、結果を「一致／合わない／確かめられない」で報告する。

1. 問の一覧に、重なりや抜けがないか（配点の合計が満点と同じか）
2. 各問で `0 ≦ got ≦ max` か
3. 各問の `got` の合計が、答案の点数と同じか

足し算は自分でせず、スクリプトにさせる。スクリプトは、このスキルのフォルダの `scripts/check_analysis.py`。

```
python3 skills/answer-sheet-review/scripts/check_analysis.py data/2026-11-rika/analysis.json
```

スキルを別の場所にコピーして使っているときは、スクリプトのパスだけをコピー先のものに替える。

- スクリプトは読むだけで、`analysis.json` を書きかえない。
- 「合わない」が出たら、答案を見直す。見直しても合わなければ、数字を合わせずに「合わない」と親に伝える。
- スクリプトが確かめるのは、形・点数の足し算・記録の決まりだけ。読み取りと原因が正しいかは確かめない。「スクリプトが通った」を「分析が正しい」と言いかえない。

## 親が確かめた後

親が本人に聞いて分かったことは、親の言葉を根拠にして書きかえる。

- 読めなかった答えが分かった：`read` を `{"status": "parent_confirmed", "text": "（分かった答え）"}` にする。
- 原因が分かった：`cause.status` を `parent_confirmed` にし、`cause.text` に親から聞いた内容を書く（例：「本人に聞いた：単位を書き忘れた」）。`tag` も付ける。
- 親が「分からなかった」と言った所は、`hypothesis` や `unknown` のままにする。
- 親が言っていないことを足さない。自分の推測で `confirmed` や `parent_confirmed` に上げない。
- 書きかえたら、もう一度スクリプトを走らせる。

## 前の回とくらべる

同じ教科の前の回の `analysis.json` があれば、古い順に並べてスクリプトに渡す。

```
python3 skills/answer-sheet-review/scripts/check_analysis.py data/2026-07-rika/analysis.json data/2026-11-rika/analysis.json
```

- 2回以上出てきたタグを、親に伝える（例：「単位や条件の見落としが、前回も今回もある」）。
- 数えるのは、確定した原因（`confirmed` と `parent_confirmed`）だけ。
- タグの付け方は回ごとにぶれる。「くり返している」と言う前に、両方の回の `cause.text` を読んで、同じ種類の間違いかを確かめる。違っていたら、そう伝える。
- 点数の上がり下がりから、原因を作らない。

## 次の工程

`analysis.json` ができたら、`test-prep-print` で復習プリントを作る。`print.json` も同じ回のフォルダに置く。
